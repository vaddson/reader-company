## Постановка общей задачи

Создать приложение, функции которого:
1. Прочитать указанную книгу в формате markdown и построить перманентный индекс.
2. Получить текстовый вопрос от пользователя, и на основе RAG построить ответ на основе данных из проиндексированной книги.

### Требования

- Консольное приложение.
- Вопросы задаются через консольный ввод текста по приглашающей строке.
- Ответы также печатаются в консоли.
- Приложение может задавать вопросы, если модель сочтет нужным.

### Стек

- Python 3.14
- RAG
- Локальная база данных по принципу Sqllite.
- LLM-модель с Ollama.
- Локальная модель для векторизации текстов.

## Предлагаемое решение

### Стек и ключевые решения
- **Без тяжёлых фреймворков** (нет LangChain): всего `requests` + чистый HTTP к Ollama. RAG на этой задаче — это ~400 строк кода.
- **LLM:** `qwen3.8:27b` (сильная, хорошо владеет русским; запасной — `deepseek-r1:32b`).
- **Векторизация:** `qwen3-embedding:8b` — уже установлена локально.
- **Хранилище:** один файл SQLite — переносимый «перманентный индекс».
- **Числа:** cosine-сходство считается в Python (несколько тысяч чанков в книге — тривиально), sqlite-vec не нужен.

### Структура проекта
```
reader/
├── main.py            # CLI: index / ask (REPL)
├── rag/
│   ├── db.py          # схема SQLite: chunks(id, doc, seq, heading_path, text, embedding BLOB), meta(модели, размерности, хэш книги)
│   ├── indexer.py     # разметка markdown, чанкинг, запись в БД
│   ├── embedder.py    # Ollama /api/embed
│   ├── retriever.py   # top-k по косинусной близости
│   └── llm.py         # Ollama /api/chat (стриминг)
└── requirements.txt   # requests (+ numpy опционально)
```

### Конвейер
1. **Индексация (`index book.md`)**
   - Разбивка на чанки вдоль заголовков markdown (400–800 токенов, overlap ~15%), к каждому чанку — путь заголовков `глава > раздел` как контекст.
   - Эмбэд батчами → SQLite (BLOB float32). Повторный запуск: хэш книги в `meta`, индекс перестраивается при изменении файла.
2. **Ретрив**
   - Эмбэд вопроса → top-k (5–8) чанков → контекст с явными именами разделов.
3. **Ответ**
   - Промпт: «отвечай только по контексту, указывай разделы книги; если вопрос неоднозначный — задай уточняющий вопрос».
   - **Механика вопросов модели** (требование из concept.md): LLM возвращает JSON-обёртку `{"type": "clarify" | "answer", "text": ...}`; при `clarify` выводим вопрос и ждём ввод пользователя, добавляем его в короткий буфер диалога (последние 3–4 хода) и повторяем запрос. Fallback — обычный ответ, если JSON не распарсился.
4. **Консольный REPL**
   - Приглашение `you> ?`, стриминг ответа посимвольно.
   - Команды: `/index <файл>`, `/model <имя>`, `/reset` (сброс диалога), `/exit`.
5. **Конфигурация** через env: `OLLAMA_HOST` (по умолчанию `localhost:11434`), `RAG_LLM_MODEL`, `RAG_EMBED_MODEL` — дефолты совпадают с установленными моделями.

### Порядок реализации
1. `rag/db.py` + `rag/indexer.py` + CLI `index` — на выходе: книга в `.db`.
2. `rag/retriever.py` — проверка качества поиска по тестовым вопросам.
3. `rag/llm.py` + REPL с стримингом и циклом уточняющих вопросов.
4. Финальные штрихи: `/reset`, обработка ошибок связи с Ollama, README.
